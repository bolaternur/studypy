## Учебная последовательность

Вывод → переменные → типы и преобразование → арифметика → ввод → сравнения → условия → циклы → списки и другие коллекции → строки → функции. PEP 8, поиск ошибок и локальный редактор идут после первой практики. Продвинутые и системные темы сохранены как дополнительные.

Git, Docker, venv, потоки, процессы, ctypes и обычные TCP-сокеты не изображаются доступными системными сервисами браузера. Объяснение различает локальный рабочий процесс и ограниченное упражнение Python. Requests разбирает готовые данные ответа; это не проверка сети. PEP 8 и аннотации типов не выдаются за автоматическую полную проверку стиля или типов.

## Совместимость прогресса

`git-practice → git`, `requests-practice → requests`, `os-pathlib-practice → os-pathlib`, `pytest-practice → pytest`, `logging-practice → logging`, `sql-practice → sql`, `algorithms-practice → algorithms`, `docker-practice → docker`, `cicd-practice → cicd`, `type-hinting-practice → type-hinting`.

Все остальные ID сохранены. `resolveLessonId()` разрешает старые ссылки; `normalizeLessonProgress()` возвращает каноническое объединение для отображения. Обе функции чистые: они не переписывают удалённые или локальные записи сами по себе. Сохранённый факт завершения старого урока не превращается в доказательство владения новым материалом.

## Выполненные проверки

`npm run validate`: 63 урока, 83 задачи, 204 проверки, 10 алиасов. Уникальные ID, правильный счётчик, отсутствие старых полей, наличие условий, эталонов, подсказок и первичных источников.

`npm run test:content`: все 63 примера и 204 проверки эталонов прошли общий раннер приложения. Все 83 стартовые заготовки отвергнуты. Для каждой задачи отвергнуты пустой текст, комментарий с ключевыми словами, `pass`, строковый литерал с ключевыми словами и `for range(5)` — 415 отрицательных проверок. Приняты 4 корректные альтернативы: `divmod`, лямбда с другой записью сложения, `sys.stdout.write`, один `print` вместо двух. Дополнительные регрессии отвергают константный return, print вместо return, print внутри возвращающей функции, дублирующий вывод и один `gold = 100`.

Проверяется неизменность исходной коллекции в `largest`, включениях, сортировке и стратегии; вызов исходной функции декоратором ровно один раз; несчитанный остаток итератора; исследование констант без исполнения функции; объект слабой ссылки вместо одной печати `True`.

Это редакторская QA известных исходников в отдельном процессе CPython, а не серверное исполнение ученического кода. В Windows sandbox создание event loop блокировалось; локальный проверочный запуск с обычными правами завершился успешно. Успех CPython не подменяет проверку доступности модулей Pyodide в браузере.
